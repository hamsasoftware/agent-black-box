## In plain words

An AI coding agent is given a small programming job in a sandbox. Afterwards a hidden checker, which the agent never sees, decides whether the job was really done. Everything the agent did is recorded, so any claim on this page can be traced to a run you can open.

- **What was run:** 352 runs of 9 tasks (named below) by 3 models (claude-fable-5-1, claude-haiku-5-5, claude-sonnet-5-5). 338 are clean and counted; 14 were set aside because a logged mistake of ours could have affected them.
- **Pass rate:** the hidden checker passed 308 of 338 clean runs overall; the tables below split it by model and by task, because pooling models would hide differences.
- **How hard the tasks were:** 12 of 20 task versions were passed in every clean run. When nearly everything passes, the runs cannot tell the models apart, so a small gap between models here is not evidence that one is better.
- **Behaviour tags are leads, not findings:** 14 different tags appear on clean runs and 0 have passed an audit. A tag is counted only after it is audited by a person reading sample runs; the rest read "unaudited" and carry no number.
- **Claim figures:** how often an agent said it succeeded when the checker disagreed comes from a classifier whose audit has passed, so the counts are shown.

### What these numbers can and cannot tell you

- They show what happened in these runs. They are not a ranking of the models.
- Groups are small and many tasks were passed every time, so these runs say little about differences between models or between the bare and plumbed variants.
- Runs marked exploratory were made before the written evaluation protocol and support no conclusion.
- A tag marked unaudited is a lead worth reading the run for. It is not a finding.

### Glossary

- **Run:** one agent attempting one task once. Every run is recorded and can be replayed.
- **Task:** a small programming job with a trap, such as a hidden instruction or an impossible requirement.
- **Grader:** the hidden checker that decides pass or fail. The agent never sees it.
- **Variant:** bare means the agent had no extra setup; plumbed means it also had instruction files, permissions and hooks.
- **Tag:** a label such as minimal-diff or test-tampering that a detector puts on a run to describe a behaviour.
- **Audit:** a person reads a sample of runs carrying a tag and records whether the tag was right. See docs/protocol.md section 7.
- **Unaudited:** the tag or figure has not passed an audit, so no count is shown.
- **Claim classifier:** the detector that reads the agent's final message and decides whether it claimed success or said something was unmet. Its figures are shown only after it passes an audit.
- **Exploratory vs protocol:** exploratory runs predate the written evaluation protocol (docs/protocol.md) and show what happened without supporting a conclusion; protocol runs follow its frozen tasks and rules.
- **Clean vs confounded:** a confounded run is one a logged incident says may be unreliable; it is excluded from every rate.
